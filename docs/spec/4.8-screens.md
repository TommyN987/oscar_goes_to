# Section 4.8: screen specifications

Part of [package 4](4-game-features.md) of [the specification](README.md).
Levels and source codes are defined in the README.

These screens were specified in words before the Figma file drew them.
Since 2026-11-19 the file's Screens page holds a frame for each one, captured from the prototype in `design/prototype/`.
Every rule here is source C (proposed by Claude, accepted by Tommy) unless it cites another rule.
All quoted copy is placeholder wording in the Figma file's voice.

## Patterns added with the frames

Rule 4.8.0.2 asks for a new pattern to be named in the file. These are named on its Design system page.

| Name | What it is |
|---|---|
| Tabs | Underlined text tabs, each with a count where it has one |
| Tag | A small capitals label on a row: "You", "Winner", "Your favorite" |
| Result status | An icon with a word: Correct, Missed or Pending (rule 6.3.3) |
| Notice | An outlined message with an icon, for information, an error or a success |
| Dialog | An eyebrow naming the subject, a serif question, what will happen, Back and one confirming action |

## Notes

- **The name step creates a half-registered player.**
  Someone who signs in and closes the tab has an account but no name.
  Rule 4.8.2.4 keeps that player off every list until they finish.
- **With no live transport, the leaderboard must say so.**
  A viewer cannot know the page is static unless it tells them, hence "Refresh to see the latest" in 4.8.5.1.
  The Refresh button in 4.8.5.4 repeats an ordinary request; it is not the mechanism ruled out in the design.
- **The results view counts only the viewer's own rows.**
  Rule 4.8.4.3 gives a sense of progress without the "N of 24 announced" line dropped in 1.4.6.
  The admin page does show a recorded count (4.8.7.5), because the admin needs to see what is left.
- **Admin results reuses the picking layout.**
  That is one fewer layout to draw and build.
